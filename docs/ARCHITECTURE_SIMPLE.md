# 🎨 Краткое описание архитектуры для схемы

## Что это за система?

Система для безопасного доступа к Telegram API с защитой от блокировок.

---

## 5 основных компонентов

### 1. 📁 Session Management
**Что:** Файл с токенами авторизации
**Где:** `data/sessions/example_session.session`
**Зачем:** Чтобы не вводить код каждый раз
**Как выглядит:** Файл с замком 🔐, права доступа 600

### 2. 🪣 Token Bucket (Rate Limiter)
**Что:** Ведро с токенами для ограничения скорости
**Где:** В памяти, управляется `limiter.py`
**Зачем:** Чтобы не превысить лимит Telegram (4 запроса/сек)
**Как выглядит:** Ведро с шариками/блоками, показывает сколько токенов осталось (например, 8/10)

### 3. 🛡️ Safe Call Wrapper
**Что:** Обертка вокруг всех API вызовов
**Где:** `limiter.py` → функция `safe_call()`
**Зачем:** Автоматическая защита всех запросов
**Как выглядит:** Щит/контейнер вокруг функции, внутри этапы: проверка → токен → выполнение → retry

### 4. 📊 Квоты (Daily Limits)
**Что:** Счетчики операций в день
**Где:** Файл `data/anti_spam/daily_counters.txt`
**Зачем:** Защита от превышения лимитов (20 DM/день, 20 Join/день)
**Как выглядит:** Прогресс-бары, файл с данными, часы для сброса в 00:00 UTC

### 5. 👥 GroupManager (High-Level API)
**Что:** Удобный интерфейс для разработчика
**Где:** `groups.py`
**Зачем:** Скрывает детали, автоматически применяет защиту
**Как выглядит:** Блок с методами (get_group_info, get_participants и т.д.)

---

## Как это работает вместе?

```
Разработчик пишет код
    ↓
GroupManager (удобный API)
    ↓
Safe Call (автоматическая защита)
    ↓
    ├─→ Проверка квот (DM/Join лимиты)
    ├─→ Получение токена из ведра
    └─→ Выполнение запроса
        ↓
    Telegram Client + Session (авторизация)
        ↓
    Telegram API (серверы)
```

## Визуальные элементы

### Цвета:
- 🔵 Синий - Session (безопасность)
- 🟢 Зеленый - Rate Limiter (контроль)
- 🟡 Желтый - Safe Call (защита)
- 🟣 Фиолетовый - GroupManager (удобство)
- 🔴 Красный - Telegram API (внешний сервис)

### Иконки:
- 📁 Session файл
- 🪣 Token Bucket (ведро)
- 🛡️ Safe Call (щит)
- 📊 Квоты (график)
- 👥 GroupManager (группа)

### Стрелки:
- Толстая → основной поток
- Тонкая → проверка/вторичный поток
- Пунктир → опционально
- Красная → ошибка/retry

## Ключевые моменты для схемы

1. **Session = авторизация без кода**
   - Файл → Клиент (чтение токенов)
   - Клиент → Файл (запись при первом входе)

2. **Token Bucket = плавное ограничение**
   - Ведро с токенами (8/10)
   - Пополнение сверху (4 токена/сек)
   - Расход снизу (1 токен на запрос)

3. **Safe Call = автоматическая защита**
   - Обертка вокруг функции
   - Внутри: проверка → токен → выполнение → retry

4. **Квоты = защита от блокировок**
   - Прогресс-бары (8/20 DM, 4/20 Join)
   - Файл счетчиков
   - Сброс в 00:00 UTC

5. **Все работает автоматически**
   - Разработчик не думает о защите
   - Все компоненты работают вместе

## Итоговая структура схемы

**Верх:** Разработчик → GroupManager
**Центр:** Safe Call (большой блок) с подключениями к Quotas и Token Bucket
**Низ:** Client + Session → Telegram API

**Сбоку:** Metrics (опционально)
