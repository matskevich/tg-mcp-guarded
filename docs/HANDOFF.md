# tg-mcp: хендоф

`tg-mcp-guarded` подключает ai-агента к вашему telegram: читать и искать переписку, выгружать материалы и выполнять явно разрешённые действия от вашего аккаунта. у чтения и записи отдельные mcp-серверы, сессии и правила доступа.

репозиторий: [matskevich/tg-mcp-guarded](https://github.com/matskevich/tg-mcp-guarded).

## что вошло в обновление 2026-09-29

- временные разрешения на текстовые отправки: конкретные чаты, срок, часы активности, квоты, ограничения ссылок и немедленный отзыв;
- поиск сообщений в одном чате и по аккаунту, пагинация истории, чтение контактов;
- чтение кнопок ботов, подтверждённые нажатия и последовательности шагов;
- закрепление сообщения и изменение требования вступить в обсуждение перед комментированием;
- вход по qr в терминале; восстановление скачивания медиа из личных чатов;
- более устойчивая работа нескольких процессов: проверка аккаунта, обнаружение занятой сессии и устаревшего владельца;
- общая сериализация сообщений и кнопок; исправлено чтение сообщений от имени канала;
- единые пути состояния, переносимый генератор конфигурации и совместимая зависимость `mcp>=1.0.0,<2`.

создание managed bot доступно как экспериментальная функция: используются временные привязки к новым методам telegram. ошибка разбора ответа может означать уже выполненную операцию. ответ `outcome_unknown=true` требует проверки владельца и управляющего бота; автоматический повтор не нужен. параметры сверены с [описанием метода](https://core.telegram.org/method/bots.createBot): `via_deeplink=true` указывается только для запроса, открытого по соответствующей ссылке.

## установить на своём компьютере

проверяемая среда: macos или linux, python 3.11+. нужны собственные `api_id` и `api_hash` с [my.telegram.org](https://my.telegram.org), свой аккаунт telegram и mcp-клиент.

```bash
git clone https://github.com/matskevich/tg-mcp-guarded.git
cd tg-mcp-guarded
python3.11 -m venv venv
source venv/bin/activate
python -m pip install -r requirements.txt
make setup-dirs
cp .env.sample .env
```

в `.env` заполните `TG_API_ID`, `TG_API_HASH` и `TG_EXPECTED_USERNAME` своим username без `@`. для аккаунта без username используйте `TG_EXPECTED_USER_ID`.

создайте свою сессию чтения:

```bash
python scripts/create_session_qr.py --session-name my_read --terminal-qr
```

qr сканируется в telegram через настройки → устройства → подключить устройство. пароль двухфакторной защиты вводится в локальном терминале. файлы сессий остаются на вашем компьютере.

сгенерируйте конфигурацию, подставив свой username:

```bash
python scripts/render_mcp_config.py \
  --repo "$PWD" --profile read \
  --read-session-name my_read \
  --expected-username your_username \
  --output .mcp.local.json
```

добавьте блок `mcpServers` из `.mcp.local.json` в настройки своего mcp-клиента и перезапустите его. генератор сохраняет абсолютные пути, путь к `.env` и python виртуального окружения. файл `.mcp.local.json` исключён из git.

первый запрос агенту: «вызови `tg_auth_status`, сверь аккаунт, затем покажи 5 последних диалогов». при несовпадении аккаунта продолжать нельзя.

## включить запись, когда она нужна

1. создайте отдельную сессию: `python scripts/create_session_qr.py --session-name my_actions --terminal-qr`.
2. повторите генерацию с `--profile full --read-session-name my_read --actions-session-name my_actions` и тем же своим username.
3. в локальном блоке `tgmcp-actions.env` укажите только нужные чаты в `TG_ACTIONS_ALLOWED_GROUPS` и свою фразу в `TG_ACTIONS_CONFIRMATION_PHRASE`. пустой список закрывает запись.
4. проверьте конфигурацию: `python scripts/check_session_paths.py --config .mcp.local.json`.
5. вызовите `tg_auth_status` и `tg_get_actions_policy` на сервере действий. перед отправкой используйте `dry_run=true`, затем тот же запрос с `confirm=true`, точным `confirmation_text` и полученным `approval_code`. минимальное ожидание — по умолчанию 30 секунд.

временное разрешение создаётся через `tg_create_write_lane`, активируется через `tg_approve_write_lane` и отзывается через `tg_revoke_write_lane`. оно ограничено текстовыми сообщениями. файлы, удаления, изменения состава и новые адресаты требуют отдельных подтверждений. [подробности](TIME_BOUNDED_WRITE_LANES.md).

## если уже пользовались старой версией

сохраните локальные изменения кода до `git pull --ff-only`. после обновления выполните `python -m pip install -r requirements.txt`. сохраните собственные `.env`, сессии, allowlist и фразу подтверждения; новую конфигурацию сначала генерируйте в отдельный файл и сравните с действующей.

пути к счётчикам, разрешениям и реестру сессий теперь привязаны к репозиторию. `TG_DATA_DIR` меняет корень для путей по умолчанию; явно заданные относительные `TG_*_FILE` разрешаются от корня репозитория. если раньше сервер запускался из другой папки, проверьте, где лежали его разрешения и счётчики. после изменения путей безопаснее заново выдать нужные временные разрешения, чем переносить неясное состояние.

при конфликте сессии ошибка показывает процесс-владелец. по умолчанию простаивающее владение может быть передано через 300 секунд; `TG_SESSION_IDLE_TAKEOVER_SEC=0` отключает передачу. новый код загружается после перезапуска mcp-процессов.

## проверка и границы

```bash
PYTHONPATH=tganalytics:. python -m pytest tests/ -q
make anti-spam-check
make telegram-api-audit
python -m pip install bandit
make security-check
```

проверены чистая установка, 184 автоматических теста и запуск обоих mcp-серверов из другой папки: 20 инструментов чтения и 41 инструмент действий. тесты используют моки; реальные отправки и новые входы в telegram при подготовке обновления не выполнялись.

ci проверяет тесты, антиспам, синтаксис/неопределённые имена и находки bandit средней/высокой серьёзности. полное выравнивание старого кода по стилю остаётся отдельной задачей; настройки `black`, `isort` и полный `make lint` доступны локально.

ограничения: `purpose` временного разрешения описывает задачу, но не проверяет смысл текста; соблюдение темы остаётся обязанностью агента. частично выполненную последовательность бота нужно продолжать с проверки результата каждого шага. ограничения telegram действуют и при соблюдении локальных лимитов.

| --- | --- |
| `tganalytics/mcp_server_read.py` | инструменты чтения |

для следующих доработок начните с [инструкции агенту](AGENT_PLAYBOOK.md), [настроек политики](ACTION_POLICY_TOGGLES.md) и тестов соответствующего модуля. сессии, секреты, переписки и файлы рабочего состояния в репозиторий не входят.
